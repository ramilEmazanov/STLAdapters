# STLAdapters — библиотека адаптеров для обработки данных на C++

Библиотека для построения цепочек обработки контейнеров и файлов через оператор `|`. Фильтрация, преобразование, разбиение текста, агрегация и объединение данных оформлены как отдельные адаптеры, которые можно комбинировать в одном выражении.

Основной акцент — обобщённое программирование, собственные итераторы и ленивое выполнение операций. Механизм пайплайнов реализован без использования `std::ranges`.

**Стек:** C++23 · шаблоны · итераторы · перегрузка операторов · filesystem · optional/expected · CMake · GoogleTest

## Идея проекта

Вместо нескольких циклов и промежуточных контейнеров задаётся последовательность действий:

```cpp
auto result = AsDataFlow(values)
    | Filter([](int value) { return value % 2 == 0; })
    | Transform([](int value) { return value * value; })
    | AsVector();
```

`Filter` ищет следующий подходящий элемент при обходе, а `Transform` вычисляет значение при разыменовании итератора. `AsVector` завершает цепочку и собирает результат в контейнер.

Такой интерфейс подходит для обработки текстов, подготовки данных, подсчёта статистики и объединения записей по ключу.

## Реализованные адаптеры

| Адаптер | Назначение |
| --- | --- |
| `AsDataFlow` | Представляет существующий контейнер как источник данных без копирования его содержимого |
| `Filter` | Пропускает элементы, удовлетворяющие предикату |
| `Transform` | Применяет функцию к элементам; тип результата выводится из функции |
| `Dir` | Обходит файловую систему с возможностью рекурсивного просмотра подкаталогов |
| `OpenFiles` | Открывает файловые потоки по путям из предыдущего этапа |
| `Split` | Читает токены из входных потоков по набору символов-разделителей |
| `DropNullopt` | Пропускает пустые `std::optional` и извлекает значения остальных элементов |
| `SplitExpected` | Разделяет результаты `std::expected` на векторы ошибок и успешных значений |
| `AggregateByKey` | Группирует элементы по ключу и обновляет накопитель пользовательской функцией |
| `Join` | Выполняет левое объединение по ключам с индексированием правого источника |
| `AsVector` | Материализует результат в `std::vector` |
| `Write` | Выводит элементы в поток с заданным символом-разделителем, включая разделитель после последнего элемента |
| `Out` | Выводит каждый элемент с новой строки |

Для объединения предусмотрены структуры `KV<Key, Value>` и `JoinResult<Base, Joined>`. Поле `joined` имеет тип `std::optional`: отсутствие совпадения сохраняется в результате явно.

Дополнительно реализован `Merge`: адаптер исключает из левого потока вхождения элементов, присутствующих в правом, с учётом их количества. В текущей демонстрационной программе показан этот дополнительный сценарий.

## Как устроен пайплайн

```text
Контейнер / каталог
        ↓
Источник: AsDataFlow / Dir
        ↓
Промежуточные адаптеры: Filter / Transform / OpenFiles / Split
        ↓
Обработка значений: DropNullopt / Join / AggregateByKey
        ↓
Результат: AsVector / Write / Out
```

### Адаптер, диапазон и итератор

Промежуточные операции разделены на объект с параметрами адаптера, диапазон с методами `begin()` / `end()` и итератор, реализующий обработку очередного элемента.

Например, `Filter` хранит предикат, `FilterRange` — предыдущий этап и предикат, а `FilterIterator` продвигается до следующего подходящего элемента. Это позволяет использовать пайплайны в `range-based for` и соединять операции без общего базового класса.

### Ленивые вычисления и материализация

`Filter`, `Transform` и `DropNullopt` обрабатывают элементы при обходе диапазона. `TransformIterator` дополнительно кэширует вычисленное значение текущего элемента, чтобы повторное разыменование не запускало функцию заново.

`AsDataFlow` хранит ссылку на исходный контейнер: он должен существовать всё время использования пайплайна. Диапазоны промежуточных адаптеров хранят предыдущий этап по значению, сохраняя объекты цепочки.

Некоторые операции накапливают данные:

- `AsVector` собирает весь результат в вектор.
- `AggregateByKey` сразу проходит входной диапазон, обновляет накопители и возвращает вектор пар «ключ — значение» в порядке первого появления ключей.
- `Join` заранее строит хеш-индекс правой стороны, а левую обходит итератором. Для одного ключа в правом индексе сохраняется одно значение.
- `SplitExpected` сразу формирует пару векторов: ошибки в `first`, успешные значения в `second`.

`Split` хранит текущий токен, поэтому его память зависит от длины токена. Объём памяти всей цепочки также зависит от типов предыдущих этапов и операций, материализующих результат.

## Пример использования

Пример фильтрует числа, вычисляет квадраты и отдельно подсчитывает частоту слов:

```cpp
#include <cstddef>
#include <iostream>
#include <string>
#include <type_traits>
#include <utility>
#include <vector>

#include "aggregate_by_key.h"
#include "as_data_flow.h"
#include "as_vector.h"
#include "filter.h"
#include "transform.h"

int main() {
    std::vector<int> values{1, 2, 3, 4, 5, 6};

    auto squares = AsDataFlow(values)
        | Filter([](int value) { return value % 2 == 0; })
        | Transform([](int value) { return value * value; })
        | AsVector();

    for (int value : squares) {
        std::cout << value << ' ';
    }
    std::cout << '\n';

    std::vector<std::string> words{"cpp", "stl", "cpp"};
    auto counts = AsDataFlow(words)
        | AggregateByKey(
            std::size_t{0},
            [](const std::string&, std::size_t& count) { ++count; },
            [](const std::string& word) { return word; });

    for (const auto& [word, count] : counts) {
        std::cout << word << ": " << count << '\n';
    }
}
```

Ожидаемый вывод:

```text
4 16 36
cpp: 2
stl: 1
```

Сохраните пример как `example.cpp` в корне проекта и соберите:

```bash
c++ -std=c++23 -Ilib example.cpp -o example
./example
```

Адаптеры реализованы в заголовочных файлах каталога [lib/](lib/). Общий заголовок [processing.h](lib/processing.h) объединяет их подключения.

## Сборка и тестирование

Понадобятся CMake версии 3.20 или новее и компилятор со стандартной библиотекой, поддерживающей используемые возможности C++23. При первоначальной конфигурации GoogleTest загружается через FetchContent, если подходящий пакет не найден локально.

Команды выполняются из корня проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Для сборки только тестов:

```bash
cmake --build build --target processing-lib-tests
```

Тесты сгруппированы по адаптерам и проверяют:

- фильтрацию и преобразования, изменение типа результата, обычные функции и лямбды;
- комбинации адаптеров и обработку константного контейнера;
- разбиение нескольких потоков, пустой ввод и последовательности разделителей;
- удаление `nullopt` и разделение успешных и ошибочных `expected`;
- агрегацию по повторяющимся и уникальным ключам, пользовательские накопители;
- левое объединение, отсутствие совпадений, пустые источники и повторяющиеся ключи слева;
- преобразование в вектор и формат вывода с разделителями.

Часть тестов предоставлена в задании; дополнительные проверки развивают сценарии композиции, агрегации, объединения и обработки граничных случаев.

## Что демонстрирует проект

- Разработку обобщённой библиотеки с композиционным интерфейсом через оператор `|`.
- Реализацию ленивых вычислений на собственных итераторах.
- Работу с выводом типов, шаблонами и пользовательскими функциональными объектами.
- Понимание владения данными и времени жизни объектов в цепочках адаптеров.
- Применение хеш-индексов для группировки и объединения данных.
- Обработку результатов через `optional` и `expected`.
- Тестирование отдельных операций и их взаимодействия в пайплайнах.
